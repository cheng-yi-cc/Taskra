# 多端同步设计草案

状态：手机与平板正式版迁移及同网同步已验证；真实设备异地双向编辑与速度仍待验收。

## 使用方式

- 手机保留现有数据并作为首次同步的数据源；空白平板通过手机生成的 8 位数字配对码加入，配对码 5 分钟内有效、使用一次后失效。
- 打开应用、网络恢复或本地数据变化后自动尝试同步；断网时仍可编辑，恢复连接后重试。
- 独立记录分别合并；同一份作业的正文和元数据作为一个整体，以最后修改版本为准。服务端保留历史，避免冲突导致旧内容立即不可恢复。
- 草稿、课程及模板、图片、录音、回收站、排序和设置均需明确处理，不能只同步作业标题。
- 排序及常用设置作为一组同步，设备本地的最近备份时间不参与同步。不同设备离线修改这组设置时按同一版本规则覆盖。
- 应用运行时约每 30 秒拉取，打开应用、联网恢复或本机内容变化也会触发；应用进程结束后，下次打开继续同步。

## 数据安全

- 读取 Room 使用事务快照；正文与内容块作为一个事务单位。文件按内容哈希校验，缺文件或校验失败时中止，不提交不完整的数据。
- 新建、更新和永久删除均须持久记录版本；删除保留墓碑，防止长时间离线的设备重新上传旧数据。版本、待上传变更和数据修改必须原子落库。
- 服务端并发写入要使用版本检查和原子提交，并保留被替换的版本。客户端仅在确认上传成功后推进同步进度；异常退出后可幂等重试。
- 在编辑器持有未提交内容时不覆盖该编辑对象；上传后等待响应期间产生的新本地变更不得被旧响应覆盖。
- 检测设备时钟异常；无法可靠比较修改时间时，按用户选择的服务器接收顺序决出当前版本，并保留被覆盖版本供恢复。客户端与服务端必须使用同一套冲突规则。
- 课程删除与关联作业并发变化、重复课程名、模板附件和草稿 ID 冲突都须在写入前处理，任何外键或唯一约束冲突都不能靠清空重建解决。
- 附件先校验和持久化，再事务性更新引用；附件清理必须考虑未同步变更、草稿和模板。
- 登录凭据不得写入代码仓库或安装包；配对码一次使用、短期有效，受访问频率限制。公网仅开放同步接口，经 HTTPS 和设备鉴权访问，不暴露数据库、管理后台或 SSH。
- 本功能不是备份。首次使用和升级有真实数据的手机前仍须按 AGENTS.md 完整备份、校验，并先在隔离模拟器验证覆盖升级。
